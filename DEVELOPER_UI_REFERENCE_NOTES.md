# Developer First UI Reference Notes

## Reference findings

HeroUI Pro demonstrates polished default states, consistent interaction affordances, responsive templates, segmented navigation, compact context controls, and production minded component craftsmanship. RaksHex should adopt that discipline in forms, cards, tabs, and empty states rather than mimic its light visual treatment.

Vercel shows how a developer platform can reduce the opening story to one category defining statement, one primary action, and a small visual proof object. Its useful pattern for RaksHex is a fast, uncluttered first impression followed by clear capability groupings.

Linear demonstrates a narrative sequence that moves from one product promise to a small number of workflow chapters. Its useful pattern is to make complex work feel organized through a consistent numbered story and realistic product surface rather than abstract feature claims.

Trigger.dev makes developer value concrete with code adjacent visuals, implementation vocabulary, and explicit reliability primitives. Its useful pattern is to expose real technical concepts without forcing visitors into a documentation page before they understand the product.

Resend demonstrates a developer friendly focus on a simple API promise, visible installation paths, and direct documentation adjacency. Its useful pattern is a short path from comprehension to first action.

Raycast demonstrates memorable product identity through an opinionated interaction metaphor, disciplined typography, and selective visual delight. Its useful pattern is to make one product behavior easy to remember rather than spread attention across many generic claims.

## RaksHex design decisions

RaksHex will use a developer first overview built around one immediate statement: it governs consequential AI actions. The product trace remains the hero proof object. The page will use a small number of workflow chapters, each tied to a specific operator concern. A short API or policy example may be introduced only where it helps a developer understand implementation, not as visual decoration.

The sign in page will remain deliberately quiet. It should reinforce the mental model of a secure workspace entry and retain the public overview as the place for product education.

No third party imagery, logos, or proprietary visual assets from the reference sites will be copied into RaksHex. The implementation will use RaksHex owned interface components, generated or internally authored abstract visual motifs, and product accurate illustrations.
